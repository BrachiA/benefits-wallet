## 🎯 הבעיה

לכל אחד מאיתנו יש היום כמה כרטיסי אשראי, מועדוני לקוחות ומועדוני עובדים. כל אחד מהם מעניק הנחות, חלקן ענקיות, אבל:

- **ההטבות מפוזרות.** הנחות מגיעות מ-**חבר**, **שלך**, כרטיסי אשראי, מועדוני רשתות ומועדוני עובדים, ולכל אחד אתר, אפליקציה ותנאים משלו.
- **קשה להחזיק את הכול בראש.** מועדון גדול נותן הנחות בעשרות ומאות חנויות. אף אחד לא זוכר אילו, ובטח לא ברגע שהוא עומד בקופה.
- **ההטבה שווה רק אם נזכרים בה בזמן.** אחרי התשלום כבר מאוחר מדי.
- **התנאים מבלבלים.** תקופת תוקף, מינימום קנייה, הטבה שלא מצטרפת למבצע אחר, סניפים שמשתתפים ושאינם משתתפים.
- **התוצאה:** אנשים משלמים מחיר מלא על דברים שהיו יכולים לקנות בהנחה. הם לא "מפסידים" כסף, פשוט לא יודעים שיש להם הטבה.

## 💡 הפתרון

**Benefits Wallet** הופך את כל ההטבות שלך לרשימה אחת, אישית וברורה.

1. **בוחרים פעם אחת** אילו כרטיסים ומועדונים יש לך (Onboarding של דקה).
2. **האפליקציה מסננת בשבילך.** מוצגות רק הטבות שבאמת מגיעות לך, לפי מה שבחרת.
3. **מחפשים בדרך שלך.** לפי מותג ("מה יש לי בפוקס?"), לפי קטגוריה, או בחיפוש חופשי שסולח על שגיאות כתיב.
4. **רואים מה שווה הכי הרבה.** ההטבות מדורגות לפי שווי כספי, והחדשות מסומנות.
5. **שומרים מועדפים** ומסתירים הטבות שלא רלוונטיות.

> המוצר מתאים במיוחד לחברי מועדונים גדולים כמו **חבר** ו**שלך**, שמעניקים הנחות על מספר עצום של חנויות וקשה לזכור את כולן.

המידע על בחירות המשתמש נשמר **על המכשיר בלבד**. אין חשבון, אין סיסמה, ולא נשמר שום מידע אישי בשרת.

## 🏗️ ארכיטקטורה

המערכת מורכבת מארבע אפליקציות סביב שרת אחד שהוא **מקור האמת היחיד**:

```
┌─────────────────┐   ┌──────────────────┐   ┌───────────────────┐
│  📱 Mobile App  │   │  🖥️ Dashboard    │   │  🧩 Chrome        │
│  (Expo / RN)    │   │  (React + Vite)  │   │  Extension (MV3)  │
│  קריאה בלבד     │   │  ניהול קטלוג     │   │  הזנה ידנית       │
└────────┬────────┘   └────────┬─────────┘   └─────────┬─────────┘
         │                     │                       │
         └──────────┬──────────┴───────────────────────┘
                    ▼
        ┌───────────────────────────┐        ┌──────────────┐
        │  ⚙️ Backend (Express/TS)  │───────▶│ Gemini (AI)  │
        │  routes → controller →    │        └──────────────┘
        │  service → repository     │        ┌──────────────┐
        └─────────────┬─────────────┘───────▶│ Cloudflare R2│
                      ▼                      └──────────────┘
              ┌───────────────┐
              │  PostgreSQL   │
              └───────────────┘
```

הארכיטקטורה תוכננה מההתחלה כ**איזון מכוון**: מספיק קלה כדי שאדם אחד יבין ויתחזק אותה, ומספיק מחושבת כדי לא לדלג על אף אחת מהנקודות שמערכת אמיתית צריכה. אלה ההחלטות המרכזיות:

### 🧠 מודל הנתונים: הטבה "נקייה" + כללי תחולה
הטבה היא ישות שלא יודעת כלל למי היא שייכת. הקישור למועדון, מותג או סניף נעשה דרך טבלת `BenefitScope`:
- **שורה אחת = AND** בין השדות שמולאו. **כמה שורות = OR** ביניהן. שדה ריק = "כל הערכים".
- כך אפשר לבטא "הטבה לכל חברי חבר בסניפי תל אביב" או "הטבה לכל מי שיש לו כרטיס מסוים בכל מותג", בלי לשכפל הטבות ובלי עמודות מיוחדות.
- כלל הנראות ממומש **במקום אחד בלבד** בשרת. האפליקציה, החיפוש וההמלצות כולם משתמשים בו, ולכן לא ייתכן מצב שמסך אחד מציג הטבה ומסך אחר מסתיר אותה.

### 🛡️ אדם בלולאה: סורק עם ציון ביטחון
כל פריט שנאסף עובר שרשרת החלטה: **התאמה** להטבה קיימת ← **ציון ביטחון** ← פרסום אוטומטי רק מעל סף מוגדר, ואחרת **תור בדיקה אנושי**.
- שינוי חריג בערך ההנחה (למשל פי 9) מוריד את הציון בצורה **לוגריתמית**, ולכן לא מתפרסם בלי אישור אדם.
- הטבה **חדשה** לעולם לא מתפרסמת אוטומטית אלא אם הוגדר שיוך ברירת מחדל מראש.
- יומן אירועים מלא (`ScrapedItem`, `ScraperRun`) מאפשר לשחזר מה קרה ומתי.

### 🔍 חיפוש חכם
חיפוש מטושטש עם `pg_trgm` (תחילית, תת-מחרוזת ודמיון) על שמות, תגיות ומילות מפתח. שגיאת כתיב עדיין מוצאת תוצאה. שליפת "עמוד נוסף" אוטומטית כשהסינון מסיר רוב המועמדים, כדי שלא יוחזר עמוד ריק בטעות.

### 🔐 אבטחה ויציבות
- הגנת סיסמה לדשבורד עם **session חתום ב-HMAC** ו-cookie מוגן, בלי מסד משתמשים מיותר.
- ולידציה ב-**Zod** על כל קלט, `helmet`, CORS מוגדר, ותגובות שגיאה אחידות.
- **סודות לא נכנסים לגיט.** `.env` מוחרג, ויש `.env.example` מתועד.
- **Soft delete** ו-`isActive` נפרדים, ו-**Audit Log** על שינויים.
- הפרדת `app.ts` מ-`server.ts` מאפשרת בדיקות בלי פורט TCP.

### 🤖 AI במקומות הנכונים בלבד
Gemini משמש לשיפוט כפילויות סמנטיות, אימות תמונה וקטגוריה וסיכום תיאורים. האינטגרציה:
- **נכשלת בעדינות.** בלי מפתח, המערכת ממשיכה לעבוד והשלב הזה מדולג.
- **מכבדת מכסות.** מגבלת קצב משותפת לכל הצרכנים של המפתח.
- **מנותקת בבדיקות.** אין קריאות רשת אמיתיות לדגם בסביבת בדיקה.

### 🧪 בדיקות אמיתיות
136 בדיקות ב-15 קבצים, שרצות מול **Postgres אמיתי** ולא מול mock. כוללות בדיקות על כלל הנראות, עריכת שיוך, סף הפרסום האוטומטי, התאמה בין פריטים, תזמון, חיפוש ו-AI. מנגנון בטיחות חוסם הרצת בדיקות על כל DB ששמו לא כולל `test`.

### 🗂️ עקביות בקוד
דפוס אחיד לכל מודול (`routes → controller → service → repository → dto`), טיפוסים משותפים בין השכבות, תגובות API אחידות ו-pagination עם תקרה. הוספת ישות חדשה היא העתקת דפוס ולא המצאה מחדש.

## 🧗 הקשיים בפרויקט

הפרויקט תלוי במידע שמפוזר באתרים של גורמים שונים, ושם נמצאים רוב האתגרים האמיתיים:

| אתגר | איך זה בא לידי ביטוי | איך המערכת מתמודדת |
|---|---|---|
| **כל אתר בנוי אחרת** | אין שני אתרי מועדונים עם אותו HTML | סורק **מונחה-קונפיגורציה**: הוספת מקור היא הגדרת selectors, בלי לגעת בקוד |
| **אתרים שחוסמים סריקה אוטומטית** | `robots.txt`, חסימות לפי קצב או User-Agent, הגנות anti-bot | בדיקת robots.txt לפני כל עמוד, השהיה בין בקשות (`requestDelayMs`), User-Agent מזוהה, וכשל בודד לא מפיל ריצה |
| **אתרים שנטענים ב-JavaScript** | `axios + cheerio` לא רואה תוכן שנוצר בדפדפן | מנגנון `renderMode` קיים בסכמה. כרגע ממומש HTTP בלבד, ו-HEADLESS_BROWSER מדלג עם אזהרה ברורה (ולא נכשל בשקט) |
| **תנאי שימוש חוזיים** | `robots.txt` לא משקף איסורים חוזיים | שער נפרד: אישור ToS אנושי (ראו להלן) |
| **אתרי בנקים וחברות אשראי** | מידע אישי מאחורי התחברות, ורגישות משפטית ואבטחתית גבוהה | **לא נאסף** מידע אישי של משתמשים. הקטלוג מבוסס על הטבות פומביות, והבחירה האישית נשארת על המכשיר |
| **אתר משתנה והסורק "מצליח" עם אפס תוצאות** | ריצה ירוקה שלא מחזירה כלום היא הכשל הכי מסוכן | התראות מייל על ריצות חריגות ויומן ריצות מלא |
| **כפילויות והטבות יתומות** | אותה הטבה מופיעה בכמה מקורות בניסוחים שונים | התאמה דטרמיניסטית, ושיפוט סמנטי של Gemini כשהכללים לא מספיקים |
| **פרסום אוטומטי שגוי** | באג בציון הביטחון איפשר לשינוי של פי 9 להתפרסם בלי אדם. התגלה בבדיקות QA | ניכוי לוגריתמי יחסי + בדיקות שננעלו על קו הגבול |
| **ההיגיון "למי מגיע מה"** | שילובים של מועדון, כרטיס, מותג וסניף | מודל `BenefitScope` (AND/OR) ומקור אמת יחיד לנראות |
| **מכסות AI** | מגבלת קצב בשכבה החינמית של Gemini | rate limiter משותף ברמת המודול |

## ⚖️ היחס לנושא המשפטי

איסוף מידע אוטומטי מאתרים הוא נושא רגיש, ולכן הוא הוטמע בפרויקט כ**עיקרון תכנוני** ולא כנספח:

- **אין סריקה בלי אישור.** מקור סריקה חדש נוצר תמיד **לא פעיל**. כדי להפעיל אותו, אדם חייב לקרוא את תנאי השימוש של האתר ולתעד אישור או דחייה, **כולל שם המאשר**. השרת דוחה הפעלה בלי אישור (שגיאה 422), והדשבורד גם חוסם את הכפתור.
- **כיבוד `robots.txt`.** נבדק לפני כל עמוד, ואם הנתיב אסור הריצה נעצרת.
- **סריקה מנומסת.** השהיה בין בקשות, User-Agent שמזהה את הכלי, וקצב נמוך (ברירת מחדל: ריצה אחת ביום).
- **אדם מחליט.** כל מה שאינו בטוח עובר לתור בדיקה ידני, ובכל מקרה הטבה חדשה לא מתפרסמת לבד.
- **תוסף הדפדפן הוא כלי עזר ידני.** הוא פועל רק בלחיצה של מנהלת מחוברת, בדפדפן שלה ועל עמוד שהיא פתחה בעצמה. אין תזמון ואין הפעלה מהשרת.
- **אין איסוף מידע אישי.** המערכת לא נכנסת לחשבונות של משתמשים, לא של בנקים ולא של חברות אשראי.
- **אין מקורות מופעלים בקוד.** ה-seed לא מגדיר אף מקור סריקה.

**הערה כנה:** הפרויקט **לא הופעל בסריקה אוטומטית בפרודקשן**. ההחלטה מודעת, כי בדיקה משפטית של תנאי השימוש בכל אתר היא תנאי להפעלה. המנגנונים כאן קיימים כדי שאפשר יהיה לעשות זאת באחריות, והם אינם תחליף לייעוץ משפטי. אפשרות עתידית לצמצום הסיכון היא שיתופי פעולה ישירים עם ספקי ההטבות או הזנה ידנית בלבד.

## 🚀 הרצה מקומית

דרישות: Node.js 20+, PostgreSQL.

```bash
# 1. Backend
cd apps/backend
cp .env.example .env        # ולמלא DATABASE_URL, ADMIN_PASSWORD, SESSION_SECRET
npm install
npx prisma generate && npx prisma migrate dev && npx prisma db seed
npm run dev                 # http://localhost:4000

# 2. Dashboard (טרמינל נוסף)
cd apps/dashboard && npm install && npm run dev

# 3. Mobile (טרמינל נוסף)
cd apps/mobile && npm install && npx expo start

# 4. תוסף Chrome (אופציונלי)
cd apps/admin-extension && npm install && npm run build
# ואז ב-chrome://extensions: Load unpacked ← התיקייה dist
```

משתני הסביבה המלאים מתועדים ב-[`apps/backend/.env.example`](apps/backend/.env.example). Gemini ו-R2 אופציונליים, ובלעדיהם המערכת עובדת והפיצ'רים האלה מדולגים.

### הרצת בדיקות
```bash
cd apps/backend
npm test            # דורש PostgreSQL מקומי. המשתמש והמסד מוגדרים ב-vitest.config.ts
npm run typecheck
```
