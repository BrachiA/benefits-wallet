# Backend — מדריך קבצים

כל הקבצים כאן שייכים לשרת ה-API (Node.js + Express + TypeScript + Prisma + PostgreSQL).
כדי להריץ בפועל: `npm install`, להגדיר `DATABASE_URL` בקובץ `.env`, ואז `npx prisma generate && npx prisma migrate dev && npx prisma db seed && npm run dev`.

---

## שורש הפרויקט

**`package.json`** — רשימת התלויות (Express, Prisma, Zod, pino וכו') וסקריפטים להרצה (`dev`, `build`, `prisma:migrate`, `prisma:seed`).

**`tsconfig.json`** — הגדרות קומפילציית TypeScript לפרויקט.

---

## `prisma/` — מסד הנתונים

**`schema.prisma`** — **הקובץ החשוב ביותר בפרויקט.** מגדיר את כל 20 טבלאות המערכת (Issuer, Program, Benefit, BenefitScope, Brand, Store, Category, Coupon, Campaign, Tag, ScraperSource, ScrapedItem ועוד) כולל שדות, קשרים, ואינדקסים. כל שינוי במבנה הנתונים מתחיל כאן.

**`seed.ts`** — ממלא את מסד הנתונים בדוגמאות אמיתיות (MAX, Cal, ישראכרט, זארה, שופרסל, קטגוריות, הטבות לדוגמה) כדי שהמערכת תעבוד מיד אחרי ההתקנה, בלי להזין הכל ידנית.

---

## `src/` — קוד השרת

### קבצי הפעלה

**`app.ts`** — מרכיב את שרת ה-Express: מחבר את כל ה-middleware ואת כל ה-routes של כל המודולים למקום אחד. לא מפעיל את השרת בפועל (זה מאפשר בדיקות אוטומטיות בעתיד בלי לפתוח פורט).

**`server.ts`** — הקובץ שבאמת מפעיל את השרת (`listen`) ודואג לסגירה מסודרת בעת כיבוי.

### `config/`

**`env.ts`** — קורא ובודק את משתני הסביבה (כתובת מסד הנתונים, פורט וכו'). אם חסר משהו קריטי, השרת נכשל מיד בהפעלה עם הודעה ברורה, במקום לקרוס מאוחר יותר בלי הסבר.

### `lib/` — כלים משותפים

**`prisma.ts`** — יוצר חיבור יחיד (singleton) למסד הנתונים, כדי שלא ייפתחו חיבורים מיותרים.

**`logger.ts`** — כלי הדפסת לוגים מובנה (pino), כולל מזהה ייחודי לכל בקשה למעקב.

**`cache.ts`** — מנגנון זיכרון-מטמון פשוט (זמני, בזיכרון) למידע שכמעט לא משתנה כמו רשימת מועדונים וקטגוריות. בנוי כך שיהיה קל להחליף בעתיד ל-Redis בלי לשנות קוד אחר.

**`AppError.ts`** — מגדיר איך שגיאות עסקיות (למשל "הטבה לא נמצאה") נזרקות בצורה אחידה בכל המערכת.

**`apiResponse.ts`** — פונקציות עזר שמעצבות את כל תשובות ה-API בפורמט אחיד (הצלחה/שגיאה/רשימה עם pagination).

### `middleware/` — שכבות שרצות על כל בקשה

**`errorHandler.ts`** — תופס כל שגיאה שקורית בשרת ומחזיר תשובה מסודרת ללקוח, במקום שהשרת יקרוס.

**`requestLogger.ts`** — רושם לוג על כל בקשה שמגיעה לשרת (כתובת, זמן תגובה וכו').

**`validateRequest.ts`** — בודק שהנתונים שנשלחו לשרת תקינים (לפי הכללים שמוגדרים בכל מודול), לפני שהם מגיעים ללוגיקה העסקית.

**`notFound.ts`** — מחזיר תשובה מסודרת כשמנסים לגשת לכתובת שלא קיימת בשרת.

### `modules/` — הלוגיקה העסקית, מחולקת לפי נושא

כל תיקייה כאן מייצגת ישות אחת במערכת, ובכל תיקייה יש בדרך כלל 5 קבצים באותה תבנית:
- **`*.dto.ts`** — כללי הוולידציה: אילו שדות מותר לשלוח וביצירה/עדכון של הישות.
- **`*.repository.ts`** — השכבה היחידה שמדברת ישירות עם מסד הנתונים עבור הישות הזו.
- **`*.service.ts`** — הלוגיקה העסקית עצמה (מה מותר, מה אסור, איך מחשבים).
- **`*.controller.ts`** — מקבל את הבקשה מהאינטרנט ומעביר אותה הלאה ל-service.
- **`*.routes.ts`** — מגדיר אילו כתובות URL קיימות עבור הישות הזו.

**`issuer/`** — מנפיקי הכרטיסים (MAX, Cal, ישראכרט וכו').

**`program/`** — המועדונים והכרטיסים עצמם (כולל תמיכה בהיררכיה, למשל MAX Platinum תחת MAX).

**`category/`** — קטגוריות ההטבות (אופנה, מזון, אלקטרוניקה...), כולל תת-קטגוריות.

**`brand/`** — המותגים (זארה, שופרסל...), כולל קיבוץ מותגים (למשל קבוצת פוקס) וחיפוש דו-לשוני.

**`store/`** — סניפים פיזיים של מותגים, כולל מיקום גיאוגרפי.

**`benefit/`** — **הישות המרכזית של המערכת.** מכיל את "מנוע ההתאמה" שקובע לאיזה משתמש (לפי הכרטיסים שיש לו) כל הטבה תקפה. זה גם המודול שמחשב את "כמה ההטבה שווה" (valueScore) עבור מנוע ההמלצות.

**`coupon/`** — קודי קופון שמשויכים להטבות, כולל מעקב אחרי מגבלת שימושים.

**`campaign/`** — קמפיינים שמאגדים כמה הטבות יחד לקידום (למשל "חזרה לבית הספר").

**`tag/`** — תגיות חופשיות להטבות (לדוגמה "סוף שבוע", "1+1").

**`scraper/`** — מודול הסריקה האוטומטית של אתרים לאיתור הטבות חדשות. כולל: קביעת מקורות סריקה, בדיקת אישור תנאי שימוש (חובה לפני הרצה), זיהוי הטבות חדשות מול קיימות, וחישוב "רמת ביטחון" שקובעת אם הטבה מתפרסמת אוטומטית או עוברת לבדיקה ידנית.

**`search/`** — חיפוש-על אחד שמחפש בו-זמנית בין הטבות, מותגים, מועדונים, קטגוריות וסניפים.

**`recommendation/`** — מנוע ההמלצות: מקבץ הטבות לפי סוג (הנחות/מבצעים/נקודות), ממיין בתוך כל קבוצה בנפרד, ומסמן הטבות חדשות.
